Модульные сценарии охватывают обязательные категории, существование/активность/категорию, положительное количество, одиночные детали и дубликаты, сокеты, RAM, GPU/слоты/габариты/разъёмы, форм-факторы корпуса/платы/БП, порты/места накопителей, отсутствующие характеристики, null-входы, расчёт мощности и границу 383/384 Вт, исключение БП из секторов, интервалы 49 999,99/50 000 ₽ и пустые ценовые интервалы.

Интеграционный тест использовал настоящую отдельную PostgreSQL-базу и HTTP ShopStub. Повторное сохранение увеличивает счётчик только один раз; сохранённая цена не пересчитывается; изменение SAVED возвращает 409; доступ другого пользователя — 404; ошибка магазина — 503 с сохранением черновика. После остановки проверочных процессов данные БД сохраняются в Docker volume. Smoke-тест оставляет аккаунты с именами smoke_<случайный суффикс>/other_<суффикс> и их тестовые сборки в локальной БД.

Схемы UML в docs/uml уточняют порядок выполнения кода. Они представлены исходниками PlantUML; автоматический рендер схем и замена изображений в исходных DOCX в эту версию не входят.
