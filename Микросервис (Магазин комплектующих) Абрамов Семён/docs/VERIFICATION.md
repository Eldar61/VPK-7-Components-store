# Проверка микросервиса магазина

Дата: 8 ноября 2026 года.

- .NET 10: сборка успешна, 0 ошибок / 0 предупреждений.
- Domain: 30 тестов пройдено.
- HTTP: 28 сценариев пройдено на отдельной PostgreSQL 18, включая SQL-фикстуры истечения предложения/резерва и запросы к настоящему API Эльдара.
- Конкурентный резерв последней единицы проверен с двумя одновременно работающими экземплярами магазина и общей тестовой БД: один ответ 200, второй 409.
- Повтор confirm не добавляет продажу; резерв и отмена не входят в аналитику; обновление товара не меняет подтверждённую сумму.
- Администраторская роль, чужая корзина, отрицательные значения, отсутствующие характеристики, изменение цены и ключа операции проверены.
- В штатной PostgreSQL 17 в Docker создана схема; в Products 442 seed-записи: 61 / 55 / 62 / 57 / 50 / 88 / 69 по порядку enum Category.
- В штатной БД нет фиктивных продаж: Sales count = 0. Тестовые товары/аккаунты/заказы находятся только в отдельных pc_shop_test / pc_shop_final на локальном тестовом PostgreSQL.
- Дополнительно на штатном каталоге получены три полных комплекта через чистый API сборки; все ID принадлежат data/catalog.json. Пример состава сохранён в example-build.json.
- При остановленном API сборки подбор возвращает 503 ASSEMBLY_UNAVAILABLE, без ложного compatible=true.
- /health/ready = 200; HTTP frontend = 200; production-сборка React/TypeScript/Vite успешна. Есть информационное предупреждение Vite о размере bundle с графиками.
- Полноценная визуальная проверка браузера не завершена: browser access host недоступен; native-доступ к свёрнутому Chrome также не сработал. Проверку форм, адаптивности и диаграмм глазами нужно выполнить при запуске.
- OpenAPI выгружен с работающего API; SQL-снимок только схемы — database.sql.
- Docker image pc-shop:local собран на Linux из .NET 10 образов. Запущенный контейнер прошёл /health/ready, чтение всех 442 товаров, вход администратора и расчёт аналитики Europe/Moscow.
- Облачное размещение не выполнялось.

Тесты используют тестовые цены и остатки; не являются подтверждением физической совместимости оборудования за пределами полей текущего контракта. HTTP-тест создаёт свои фикстуры; его не нужно запускать на БД с учебными покупками, которые вы хотите использовать в отчёте.

Подтверждение изначально не генерирует демо-продажи. Чтобы получить реальные для учебного сценария графики, создайте и подтвердите покупки на сайте.
